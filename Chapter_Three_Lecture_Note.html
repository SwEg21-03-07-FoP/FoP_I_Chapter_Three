Program Flow Control

Selection (if, if-else, else-if, switch), looping (for, while, do-while), and jump statements (break, continue, return).

New to flow control? Start hereIn Chapter 2 your programs ran one statement after another, top to bottom. This chapter gives you three new powers: choose between paths, repeat a block of code, and jump out of or skip part of a repeat. Every construct below follows the same pattern: an explanation, its syntax, a one-sentence summary, an everyday analogy, two running case studies (a café and a bus terminal), and a complete working example. Read in order and type every example yourself.

Learning objectives

By the end of this chapter you will be able to:

  • explain, in everyday words, what each selection and loop statement does;
  • choose the right construct — if, if-else, else-if, switch, for, while, or do-while — for a given problem;
  • trace a flowchart or Pseudocode for a selection or loop statement by hand;
  • write correctly nested if-else statements and avoid the dangling-else trap;
  • write count-controlled loops with for, and event-controlled loops with while or do-while;
  • use break and continue correctly inside a loop, and know when not to use goto;
  • recognize and avoid the common mistakes beginners make with each construct.

3.1 What is flow control?

  • A running program spends its whole time executing statements (instructions) one at a time
  • The order in which the instructions are run or executed is called the program flow
  • By default, the program flow is sequential: top to bottom, in the order they are written.
  • Flow control statements let the programmer to change that order: branch to a different statement, or repeat a block of statements.
  • There are three basic flow constructs: sequential (default), selection (decision), and repetition (loop).

The three basic flow patterns, drawn with the same symbols used throughout this chapter: an oval for Start/End, a rectangle for a step, and a diamond for a decision with its True/False exits.

In plain wordsWithout flow control, a program is a straight road. Selection statements are junctions: the program takes one branch or another. Loops are roundabouts: the program goes around until a condition tells it to exit.

3.2 Revision: blocks and statements

  • A statement is one instruction, ending with a semicolon.
  • A block (or compound statement) is a group of statements inside braces { }.
  • To the compiler, a block counts as a single statement.
  • Blocks can be nested inside other blocks.
  • Most control structures expect one statement to be executed by default.
  • If you want several statements to be controlled by flow structure, you must wrap them in braces.
flow control statement
{
    statement1;
    statement2;
    statement3;
}
Careful: Every selection and loop statement controls exactly one statement after it. If you forget the braces around several statements, only the first one is actually inside the if or loop — a very common beginner bug.

3.3 Selection statements

Selection statements also called decision statements choose whether, or which, statements run, based on a condition evaluated at run time. Most programming language including C++ provides four Selection Statements: if, if-else, the else-if ladder, and switch.

The following section discuss each one of them with their syntax, using real world an analogy, case studies, and a complete worked example.

3.3.1. The if Statement

It is sometimes desirable to make the execution of a statement dependent upon a condition being satisfied. The if statement provides a way of expressing this and allows for conditional execution.

The if statement flow control:
  • Executes a statement or block of code only if a condition is true or satisfied.
  • There is no “otherwise” action — if the condition is false or not satisfied, the execution simply continues with whatever instruction comes after the if statement.

(i) Syntax

if (boolean expression) {
    // block of statements;
}
next statement(s);
What each part means?
  • Boolean expression: It is expression that must evaluate to a boolean (true/false)
  • Usually built from relational expression(s) (<, >=, == ...) that can be connected using logical operators (&&, ||, !), refer back to Chapter 2.
  • When the expression is true, the block is get executed, then execution continues with what follows.
  • Otherwise, if the condition evaluated to false, the block is skipped entirely, and execution continues with what follows.
  • next statement(s) always runs, whether or not the if-block executed.
In one sentenceDo something only when a condition is true and continue with normal execution.

(ii) Everyday Analogy

If it is raining, take an umbrella. If it is not raining, you simply carry on.
There is no “otherwise” action. You simply carry on with your daily work.

3.3.2. The if-else statement

It is the extension of the basic if statement by adding the else clause (i.e. it provides the option to specify what we want to happen if the condition is not fulfilled by using the keyword else). In simple terms:
  • It adds an else branch and make the program to choose between two actions (block of codes).
    one action executed when the condition is true, and a different action executed when it is false.
  • Exactly one of the two branches runs — never both, never neither.

(i) Syntax

if (boolean expression) {
    statement1 / block1;
}
else {
    statement2 / block2;
}
next statement(s);
What each part means
  • When the boolean expression is evaluated to True, block1 executed and block2 is skipped.
  • Otherwise when the boolean expression is false, block2 executed and block1 is skipped.
  • Braces may be omitted when a branch has only one statement, but keeping them is recommended — it protects you if you add a second statement later.
In one sentenceExecute exactly one of the two actions — never both, never neither.

(ii) Everyday analogy

A fork in the road: left or right. You take one, never both and never neither.
A traffic light works the same way: green go, otherwise stop.

3.3.3. Nested if-else and the Dangling else

A selection statement may contain another selection statement — this is called nesting statement.
A common pattern nests an if-else inside the else branch of another:

Example: 
if (ch >= '0' && ch <= '9')
    kind = digit;
else {
    if (ch >= 'A' && ch <= 'Z')
        kind = upperLetter;
    else {
        if (ch >= 'a' && ch <= 'z')
            kind = lowerLetter;
        else
            kind = special;
    }
}

When if..else statements are nested, the compiler always matches else with the nearest unmatched if above it.

Note: If your intention does not match that rule, the result is the common dangling else problem.

See the example below which demonstrate this problem. 

if (i == 0)
    if (j == 0)
        cout << "i and j are zero" << endl;
else cout << "i is not zero" << endl;

In this example the else looks like it matches the OUTER if, but the compiler attaches it to the inner if(j == 0), not the outer one.

So when i is not 0, nothing is printed — not what the indentation suggests.
This problem is fixed by explicitly adding braces as follow: 

if (i == 0) {
    if (j == 0) cout << "i and j are zero" << endl;
}
else {
    cout << "i is not zero" << endl;   // now no ambiguity: the else matches the outer if
}
Rule of thumb:When you nest an if inside another if's branch, add braces. It costs nothing and removes any doubt about which if an else belongs to.

3.3.4. The if-else-if ladder

The if … else statement allows for conditional execution based up on two alternatives only. If you have more than two possible alternatives, you can link together a sequence of if … else statements.
This construction is called if … else if statement or else if ladder.

In simple terms:
  • This conditional flow control is used for a problem that has more than two alternatives
  • It formed by chaining if-else statements together.
  • Conditions are tested from the top to down.
    The first condition that is evaluated to true is execute its block, and the rest of the ladder is skipped.

(i) Syntax

if (boolean expression 1) {
    statements1;
}
else if (boolean expression 2) {
    statements2;
}
else if (boolean expression 3) {
    statements3;
}
.
.
.
else {
    default_statements;
}
What each part means
  • The boolean expression for each else if ladder is evaluated to True / False
  • Only one block in the whole ladder ever executes: the one attached to the first true condition.
  • The final, plain else is optional — it catches every case not covered by else if ladder.
  • Order matters: test the most specific or narrowest condition first; the broadest or default case goes last.
In one sentenceTest several conditions in order; the first true condition executed and the rest skipped.

(ii) Everyday analogy

A ticket office with price for groups of people: child, student, adult, senior. It is checked from the top-down and get the first group that fits.
Exam grades work the same way: 80 or more is A, 70 or more but less than 80 is B, and so on.
In this case the default is possibly the grade is F.

3.3.4. The switch statement

The switch statement is similar to if...else ladder, it enables you to test several cases generated by a given expression. But it is more specialized because:
  • it tests one expression against several exact constant values.
  • unlike else ifladder, here the condition have the form (var == const), where var is a variable and const is a literal constant.
  • the switch tag must produce a value of type char, short, int, or bool result — never float, double, or long.

The switch statement has four components: Switch, Case, Default, Break, where Default and Break are Optional bur recommended.

(i) Syntax

switch (expression){
    case constant1:
        statements1;
        break;
    case constant2:
        statements2;
        break;
    .
    .
    .
    default:
        default_statements;
}
What each part means
  • expression results in a value that (the switch tag) is compared against each case that specify constant value, in order from top to down, until a match is found.
  • When match found, execution runs from that case until a break is reached, or the switch ends.
  • Without break statement, the execution falls through into the next case — sometimes a bug, sometimes used deliberately to share one action between several cases.
  • default runs when nothing matches. It is optional, as is break on the very last case — but omitting break elsewhere is usually a mistake.
In one sentenceCompare one value against a list of exact choices (literal constants).

(i) Everyday analogy

A vending machine or a lift: press 1 for the first floor, 2 for the second, and so on. The machine reads one value and goes to the matching button. A button that is not on the panel does nothing.

3.4 Looping

A loop repeats a block of statements. There are two ways to know when a loop has repeated enough:

Count-controlled

You know in advance exactly how many repeats are needed. Needs: an initialization of a counter, a test of the counter, and an update of the counter each pass.

Event- (condition-) controlled

Repeats until something happens inside the loop. Three common kinds:
  • Sentinel-controlled: stop when a special value (not a valid data value) is entered.
  • End-of-file controlled: stop when there is no more data to read.
  • Flag-controlled: stop when a boolean flag changes inside the loop.

C++ provides three loop statements: for, while, and do-while.

1) The for loop

  • Best suited to count-controlled loops: it has dedicated places for the counter’s start, test, and update.

Syntax

for (initialization; condition; update)
{
    statement(s);
}
What each part means
  • initialization runs once, before the loop starts (usually declares and sets a counter).
  • condition is checked before every pass. True → run the body; false → the loop ends.
  • update runs at the end of every pass, then control returns to the condition.
  • Any part may be left empty (but the two semicolons are always required); for (;;) is a deliberately infinite loop.
In one sentenceRepeat a known number of times, with the counter built in.

Everyday analogy

Climbing 10 stairs, or running 4 laps of a track. You know the count in advance and you count as you go.

2) The while loop

  • Repeats a statement while a condition holds.
  • The condition is tested before each pass (test-first), so the body may run zero times.

Syntax

while (expression)
{
    statement(s);
}
What each part means
  • expression is checked before every pass. True → the body runs once more; false → the loop ends immediately.
  • Nothing about a while loop is automatic — initializing and updating the variable the condition depends on are both the programmer’s job.
  • If expression is false the very first time, the body never runs at all.
In one sentenceRepeat while a condition holds; the test comes first, so it may run zero times.

Everyday analogy

Fill a bucket while it is not full. If the bucket is already full, you do not pour at all. The check happens before each pour.

3) The do-while loop

  • Like while, but the condition is checked after the body runs.
  • The body always executes at least once, even if the condition is false from the start.

Syntax

do
{
    statement(s);
} while (expression);
What each part means
  • The body runs first, unconditionally.
  • expression is then checked. True → go around again; false → the loop ends.
  • Note the semicolon after while (expression) — easy to forget.
In one sentenceRun the body first, then test; it always runs at least once.

Everyday analogy

Taste the soup, then decide whether it needs more salt. You must taste at least once. An ATM asks for your PIN at least once, then asks again while it is wrong.

3.4.4. Nested loops

Loops can contain other loops, to any depth.

for (int i = 1; i <= 3; ++i)
{
    for (int j = 1; j <= 3; ++j)
    {
        cout << "(" << i << "," << j << ") ";
    }
}
// output: (1,1) (1,2) (1,3) (2,1) (2,2) (2,3) (3,1) (3,2) (3,3)
Scope in nested loopsA loop counter declared with for (int i = ...) exists only inside that loop. Two different loops — even nested ones — may each declare their own variable named i without clashing, because each i’s scope is its own loop.

3.5 Jump statements

Jump statements interrupt the normal flow of a loop, switch, or function: break, continue, and (inside main) return. C++ also has goto, which is explained but discouraged.

break: leave the loop (or switch) now

  • Inside a loop, break exits the loop immediately, even if its condition has not become false.
  • Also used inside switch, where it stops fall-through into the next case.

Syntax

break;
What each part means
  • Takes no arguments — just the single keyword and a semicolon.
  • Affects only the nearest enclosing loop or switch; using it anywhere else is an error.
  • Execution continues with the statement immediately after the loop or switch.
In one sentenceLeave the loop or switch immediately.

Everyday analogy

A fire alarm: you leave the building immediately, not after finishing your work. Or searching for your friend in the cafeteria: stop looking once you find them.

        if (portions > stock) {
            cout << "Not enough injera. Stop serving." << endl;
            break;                      // leave the loop now
        }
        stock -= portions;
        cout << "Served. Stock left: " << stock << endl;
    }
    cout << "Closing stock: " << stock << endl;
    return 0;
}

Without break, a loop only ends when its own condition becomes false. break gives a loop a second, early way to end:

continue: skip this round, keep looping

  • continue skips the rest of the current pass and jumps straight to the next one.
  • In a for loop that means jumping to the update expression; in while/do-while, to the condition test.

Syntax

continue;
What each part means
  • Takes no arguments — just the single keyword and a semicolon.
  • In nested loops, continue applies only to the innermost loop that contains it.
  • The loop itself keeps running; only the rest of that one pass is skipped.
In one sentenceSkip the rest of this pass and go straight to the next one.

Everyday analogy

Skipping a song on a playlist: you do not stop the music, you just move to the next song.

return: finish the job and hand back a result

  • return ends the current function immediately.
  • Inside main, it ends the whole program; the value given is the program’s exit code (Chapter 2: 0 for normal, non-zero for abnormal).

Syntax

return expression;
What each part means
  • expression is optional for a function returning void, required otherwise — in main, an int.
  • Execution leaves the function at once; any statements after return in the same block never run.
  • Unlike break and continue, return can carry a value back to whoever called the function.
In one sentenceEnd the function now, optionally handing back a value.

Everyday analogy

The goto statement (avoid)

  • goto jumps unconditionally to a labeled point in the same function.
  • Neither case study uses goto — every example that uses it can be rewritten with a loop, and should be.

Syntax

goto label;
...
label:
    statement;
What each part means
  • label is an identifier followed by a colon, marking a point in the code.
  • goto label; jumps straight to that point, skipping everything in between.

Example

int n = 10;
loop:                 // a label
cout << n << ", ";
n--;
if (n > 0) goto loop;
cout << "FIRE!" << endl;

Comparison with loops

goto for / while / do-while
Structure ignores nesting and scope clearly bounded block, with its own scope
Readability jumps can land anywhere, hard to trace the loop body is easy to find and read
Recommended? no — shown here only so you can recognize it yes, always prefer these

Ending a program immediately: exit and abort

  • return (just discussed) only ends the current function — in main, that ends the program. Sometimes a program needs to stop immediately from inside some other function, for example right after an unrecoverable error.

Syntax

exit(code);         // ends the program immediately, from anywhere
abort();            // ends the program abnormally, usually after a fatal error
What each part means
  • Both need #include <cstdlib>.
  • exit(code); ends the whole program at once, no matter which function calls it — 0 means normal, non-zero means abnormal, exactly like returning from main.
  • abort(); ends the program at once, signalling a serious, unrecoverable error; it takes no exit code.

Example

if (errorCount > 10) {
    cout << "too many errors" << endl;
    exit(-1);      // or: abort();
}

Comparison with return

Statement Header needed Can be called from
return code; (in main) — only main itself
exit(code); <cstdlib> any function, anywhere in the program
abort(); <cstdlib> any function, anywhere, for abnormal termination

Choosing the right construct: quick guide

Ask yourself Use
Must some step happen only sometimes? if
Two ways, choose exactly one? if-else
Several bands or ranges, first match wins? else-if ladder
One value against exact choices? switch
Do I know how many times? for
Repeat until a condition changes, maybe zero times? while
Must it run at least once? do-while
Stop the loop early? break
Skip just this round? continue

Common misconceptions and how to answer them

Students think… Why Fix (use the analogy)
if and else both run They read the code like a list A fork in the road: you take one path only
In an else-if ladder every true condition runs They test conditions separately First door that opens wins; the rest are skipped
switch only runs the matching case They forget break Water flowing down steps: without break it keeps flowing into the next case
A for loop runs one time too many or too few Counting the stops instead of the steps Fence posts: 12 cups, start 1 and stop at 12
while always runs at least once Mixing it up with do-while while checks the door first; do-while checks after you walk in
An endless loop is a computer fault They forget the update A lift stuck because nobody pressed “stop”: the counter never changes
= and == are the same Maths habit = puts a value in the box; == asks “are they equal?”
break stops the whole program The word sounds big Break leaves one loop, like leaving one room
continue is the same as break Both “skip” something Continue skips one song; break stops the music

Glossary

Flow of control
The order in which a program’s statements execute.
Selection statement
A statement that chooses which block runs, based on a condition: if, if-else, else-if, switch.
Dangling else
An else that the compiler attaches to the nearest unmatched if, which may not be the if the programmer intended.
Fall-through
In a switch, continuing into the next case because the current one had no break.
Count-controlled loop
A loop that repeats a known number of times, using a counter.
Event-controlled loop
A loop that repeats until a condition changes: sentinel, end-of-file, or flag controlled.
Sentinel value
A special value used to signal “no more data” — not a valid data value itself.
Infinite loop
A loop whose condition never becomes false (often caused by forgetting the update).
break
Exits the nearest enclosing loop or switch immediately.
continue
Skips to the next iteration of the nearest enclosing loop.
Nested loop
A loop placed inside another loop.
